Creation Chronicle

Catatan historis perubahan implementasi dan artefact HIKARI/.LAB. Kondisi terkini ditentukan oleh source, tests, STATE, BACKLOG, dan release manifest.

2026-10-10 — Version 0.6.8: Editable release-note drafts

The release preparation flow now supports previewing generated notes, editing multiline Markdown, loading saved drafts, and saving drafts by project and target version outside the target repository. Draft actions do not mutate Git state; existing release confirmations and guards remain in force, and non-interactive --yes continues to use generated notes without prompts.

2026-10-10 — Version 0.6.7: Operation-specific outcome summaries

Action history now records concrete read-only and local utility results instead of generic fallback text. Utility success/warning/error feedback uses the same active tracker as Git workflows, and summaries retain useful partial-success or skipped-publication context without storing command output or credentials.

2026-10-10 — Version 0.6.6: Outcome-accurate action history

New interactive action-history entries now use SUCCESS, FAILED, CANCELLED, or BLOCKED based on terminal feedback, with concise result summaries. Explicit cancellations and Local Mode Git-readiness blocks are distinguished from success. Outcome tracking also covers local utility feedback while retaining bounded history outside the target repository and excluding command output/credentials.

2026-10-10 — Version 0.6.5: Real Git integration and artifact lineage

Added disposable real-Git integration coverage for remote tag lookup, successful absence, remote deletion, and unreachable remote failures. Exact-artifact preflight now checks boot/continuation version references and release manifest/changelog lineage. Authenticated GitHub smoke testing remains pending because GitHub CLI is unavailable in the validation environment.

2026-10-10 — Version 0.6.4: Fail-closed remote tag verification

Remote tag lookup now distinguishes successful absence from an unknown remote state. Network/authentication/remote command failures raise GitError, and remote tag deletion cannot proceed when verification fails. Three regression tests cover lookup failure, deletion guard, and successful absent-tag lookup.

Release Manager tag-list refresh now loops iteratively instead of recursively, preventing unbounded call-stack growth after repeated refreshes. Continuity documents were corrected to the current 12-operation dashboard and 0.6.2 capabilities were reclassified from Unreleased to implemented. Regression tests cover refresh and destructive-action cancellation.

2026-10-10 — Version 0.6.2: Release state and documentation synchronization

Current-state documentation and machine-readable boot metadata were aligned with the implemented 12-operation dashboard, nested Release Manager, repository profile generator, and backup restore. The patch changes documentation and version metadata only; the canonical unittest suite and exact ZIP Artifact Compliance Gate were run against the resulting package. Authenticated live GitHub behavior remains environment-dependent.

2026-10-10 — Version 0.6.0: Hybrid Dashboard + Full Operations

The main screen now combines the explicit target project path, live project-health snapshot, and the full operation list (1–15). TARGET, DASHBOARD, and OPERATIONS use consistent horizontal separators. The dashboard remains read-only and preserves local-first safety behavior.

2026-10-08 — Version 0.4.2: Hybrid project workflow

HIKARI/.LAB menambahkan Local Mode untuk proyek sebelum inisialisasi Git, deteksi versi local-first, operasi remote-aware, smart PUSH dengan pilihan commit eksplisit, release notes berbasis changelog, pengelolaan .gitignore yang menjaga file existing, warna terminal semantik, dan pembersihan operation log.

2026-10-09 — Version 0.4.3: Artifact validation and continuity repair

Release preflight diperbaiki agar valid pada ZIP flat-root yang tidak menyertakan entri direktori eksplisit untuk src/ dan tests/. Release manifest yang stale diganti dengan lineage HIKARI/.LAB; versi package dan continuity snapshot disinkronkan. Payload glossary yang ada dipertahankan dan tidak diubah oleh pekerjaan validasi artefact ini.

2026-10-09 — Version 0.4.6: Guided release recovery

RELEASE tidak lagi langsung buntu ketika catatan versi tidak ditemukan: HIKARI menampilkan draft transparan yang diturunkan dari commit dan menandai sumbernya agar ditinjau sebelum publikasi. Metadata versi package dan CLI diselaraskan dengan VERSION. Perubahan ini tidak menulis changelog secara diam-diam; preview/edit tersimpan tetap menjadi pekerjaan backlog.

2026-10-09 — Version 0.4.7: Hybrid release controls

RELEASE kini menyediakan Quick Release, Force Release Current, dan Custom Version agar versi target tetap menjadi keputusan pengguna. Publikasi tidak lagi melakukan stage/commit diam-diam pada working tree yang kotor, menolak tag lokal/remote atau GitHub Release duplikat, dan berhenti jika status remote tidak dapat diverifikasi. Versi artifact diselaraskan ke 0.4.7.

2026-10-09 — Version 0.4.8: Release Manager

Added a dedicated RELEASE MANAGER entry and CLI command to inspect GitHub Releases, delete a release object without silently deleting its tag, and manage local/remote Git tags as separate confirmed actions. The implementation favors explicit destructive confirmation and preserves the distinction between GitHub Release records and Git tags.

2026-10-09 — Version 0.4.9: Conservative Undo / Redo

Added a dedicated UNDO / REDO utility. Commit undo is implemented as a new revert commit, redo is limited to reversing an immediately preceding revert commit, and file restoration is restricted to explicitly selected unstaged tracked-file changes. Commit undo/redo refuses dirty working trees; staged and untracked files are not silently discarded.

2026-10-09 — Version 0.5.0: Action Status visibility

Added ACTION STATUS to surface live repository state and a bounded per-project history of HIKARI action flows. History is stored outside the target repository and excludes command output and credentials; logging is best-effort and does not block Git operations.

2026-10-09 — Version 0.5.1: Unified Status

Integrated recent HIKARI action history into menu 1 STATUS, combining project health and action visibility without adding another top-level menu entry. Kept the direct CLI action-status alias for compatibility.

2026-10-09 — Version 0.5.2: Informative Status & Scan

STATUS and SCAN were upgraded from terse summaries to actionable project reports: location, scan timestamp, directory/file counts, total size, latest modified file and timestamp, file-type mix, largest files, and relevant Git context. The shared target panel continues to provide context for the other operations.

2026-10-09 — Version 0.5.3: Beginner-friendly Git Guide

Added a dedicated plain-language Git Guide for new users, explaining commit, push, pull, Pull Request, branch, remote, tag, release, clone, merge, and .gitignore. Main-menu descriptions and inline explanations now distinguish similar concepts and call out the destructive risk of FORCE SYNC. Onboarding documents were synchronized with the new beginner-first flow.

2026-10-10 — Version 0.6.2: Unified Release Hub

Menu 6 now groups release creation and release/tag management. The standalone top-level RELEASE MANAGER entry was removed, later dashboard operations were consolidated into the current 12 top-level operations, and the release-list query stopped requesting the unsupported gh JSON field url. Destructive operations retain explicit default-N confirmations.

v0.5.4 — Git History & Auto Troubleshoot

Added recent commit/tag history and read-only diagnosis for common remote, upstream, divergence, and unrelated-history problems. Recommendations are explicit; no automatic destructive recovery.

v0.5.5 — Category Dashboard & Git Readiness

Grouped operations into five categories with focused submenus. Added contextual readiness guidance for Git-dependent operations in Local Mode and clearer missing-remote guidance, while keeping initialization local-only and avoiding implicit uploads.

v0.5.6 — Auto-clear Dashboard History

Clears stale terminal output before dashboard and category submenu redraws so mobile navigation does not accumulate prior operation logs.

v0.5.8 — Navigation polish

Restored the HIKARI banner after screen clears, added explicit exit/back controls, and standardized hybrid navigation: numeric dashboard categories and operation IDs, B for back, and X/0 for exit.

v0.5.8 — Hybrid navigation

Restored numeric dashboard category and operation selection while reserving B for back and X/0 for exit. This removes shortcut collisions and preserves banner redraw and screen clearing.

0.5.10 — Consistency and Safety Remediation

The 0.5.10 continuation consolidates package/CLI/banner version resolution, adopts the simple/advanced dashboard as the current UI, and repairs test discovery so the canonical standard-library unittest command exercises legacy function tests. Filesystem scanning now shares exclusions and skips symlinks; GitRepo and LocalProject use the same local version detector. Additional safety work improves release race handling, action-history warnings, GitHub repository-name validation, explicit origin replacement, and utility command/SQL construction. A Python 3.10–3.12 GitHub Actions workflow was added. Final release claims are tied to the exact packaged ZIP and its extracted test/preflight result.

Version 0.6.2 — Repository Profile Generator

Menu 11 GITHUB REPO now offers an opt-in deterministic generator for GitHub About and Topics when creating a new repository. It derives suggestions from local project metadata and README, previews them before creation, permits editing the About text, and uses separate default-N confirmations for generation and remote creation. About is passed to GitHub CLI during creation; Topics are applied afterward. No external AI service is used and project files are not pushed. Authenticated live GitHub behavior remains an environment-dependent validation gate.
